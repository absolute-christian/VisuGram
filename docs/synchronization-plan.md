# Синхронизация VisuGram

Клиент → HTTPS API на Railway → SQLite на постоянном диске. GitHub хранит исходники и собирает приложение. Пользователи одного сервера видят визуальные профили и подарки друг друга.

## Аккаунт и общие данные

Записи привязаны к числовому Telegram ID. Настоящий редактируемый юзернейм обновляется при синхронизации независимо от визуального режима. Визуальные имена хранятся отдельно и не отправляются в Telegram как настоящие.

По выбранной схеме нет бота и проверки личности. Сервер доверяет ID клиента; изменённый клиент может его подставить. Это прототип, а не защищённое подтверждение аккаунта.

БД содержит профили, закреплённые объекты, подарки, результаты повторяемых операций и курсоры изменений. Уникальные ключи и транзакции предотвращают одновременное назначение объекта разным ID. При передаче NFT прежняя запись остаётся в истории без права закрепления.

## Клиент

Адрес задаётся в «Редактировать профиль → Сервер синхронизации». Назначения подтверждает сервер. Собственные изменения проверяются раз в минуту; чужие профили загружаются при открытии. В выключенном визуальном режиме данные кэшируются без декодирования моделей для отображения.

Цена имени или номера берётся с Fragment с сохранением типа цены: последняя продажа, предложение, ставка. Подтверждённо отсутствующее имя получает стабильные 7–10 TON. Неизвестный +888 номер не допускается; ошибка сети не считается отсутствием.

Старые локальные записи не импортируются автоматически. Их исходные даты и сообщения сохраняются. Для закрепления объекта в общей БД его нужно оформить через подключённый сервер.

## Подключение

Общий сервер: `https://visugram-api-production.up.railway.app`. Укажите этот адрес в «Редактировать профиль → Сервер синхронизации» на каждом клиенте. Перед подключением прочитайте [проект политики обработки данных](privacy.md).

Сервер поддерживается отдельно от клиента в приватном репозитории `VisuGram-Backend`. Railway развёртывает его из ветки `main`; SQLite хранится на постоянном Volume `/data`. Изменения клиента не перезапускают API.

Используется пробный бесплатный тариф Railway. Сохранение сервиса после окончания пробного периода зависит от лимитов и доступных кредитов Railway.
