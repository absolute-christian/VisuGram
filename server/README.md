# Сервер VisuGram

Синхронизирует визуальные профили и подарки между клиентами одного сервера. Данные хранятся в SQLite. Python не требует дополнительных библиотек.

Это прототип без подтверждения Telegram ID: клиент передаёт его в заголовке запроса. Уникальность объектов проверяется атомарно, но изменённый клиент может подставить чужой ID. По выбранной схеме здесь нет бота и подтверждения владения аккаунтом.

## Railway Free

Используется один сервис с постоянным диском. Отдельные PostgreSQL, Redis и HTTPS-прокси не нужны.

1. Создайте сервис из репозитория `absolute-christian/VisuGram`, ветка `dev`.
2. В Source задайте **Root Directory: `/server`**. Railway обнаружит Dockerfile в этой папке и соберёт только сервер, без Telegram Desktop.
3. Добавьте постоянный Volume и подключите к сервису с **Mount Path: `/data`**. База находится в `/data/visugram.sqlite3`.
4. В Deploy задайте **Healthcheck Path: `/health`**, одну реплику и рестарт при ошибке. В Watch Paths укажите `/server/**`, чтобы изменения клиента не перезапускали API.
5. В Networking нажмите **Generate Domain**. Railway выдаст адрес `https://….up.railway.app` и обеспечит HTTPS.
6. Этот адрес укажите в VisuGram: **Редактировать профиль → Сервер синхронизации**.

Переменную `PORT` назначает Railway; приложение её использует. Dockerfile слушает `0.0.0.0`. Если сервис уже создан с другим способом запуска, задайте команду `python /app/app.py`.

Без Volume база размещается на временном диске и может исчезнуть при новом развёртывании. Не удаляйте Volume с рабочими данными. Размер диска ограничен тарифом; резервные копии нужно хранить отдельно.

На момент подготовки Railway Free предоставляет $1 кредита ежемесячно, до 512 МБ RAM и 0,5 ГБ Volume. Новый Trial имеет отдельные временные условия. Это лимиты ресурсов, а не обещание бесплатной непрерывной работы: длительность зависит от расхода кредита. Не подключайте платный план автоматически. Актуальные условия: [планы](https://docs.railway.com/pricing/plans), [Trial](https://docs.railway.com/pricing/free-trial), [Volume](https://docs.railway.com/volumes).

На Limited Trial исходящая сеть может быть ограничена. Если Fragment недоступен, проверка коллекционных номеров и цен завершится ошибкой; сервер не выдаст неизвестный номер или случайную цену вместо сетевой ошибки.

## Обмен данными

Оба пользователя должны подключиться к одному серверу. После первого подключения регистрация происходит автоматически. Настоящий редактируемый Telegram-юзернейм обновляется независимо от переключателя визуального режима.

Изменения проверяются раз в минуту. Чужие профили запрашиваются при открытии. В выключенном визуальном режиме серверные записи сохраняются в кэше без декодирования моделей для отображения. Ресурсы карточек загружаются по мере показа.

Новые визуальные имена, телефоны и NFT закрепляются за Telegram ID в одной транзакции. Для имени хранится отдельно выбранное положение в профиле. Настоящие Telegram-юзернеймы не меняются.

Номера допускаются только в формате +888 и при подтверждённом наличии на Fragment. Цена берётся с публичной страницы объекта. Последняя продажа, предложение, текущая и минимальная ставки сохраняются как разные типы цены. Универсальный официальный API Fragment сервер не использует; изменение разметки может временно нарушить проверку.

При подтверждённом отсутствии имени создаётся визуальная цена 7–10 TON. Она сохраняется и не меняется случайно при повторной проверке. Если реальные данные появятся позднее, они могут заменить сгенерированную цену. Сетевые ошибки не считаются отсутствием объекта.

Подарки сохраняют дату, комментарий, отправителя, получателя, цену и валюту. Только получатель управляет отображением и закреплением. Повтор одной операции не создаёт второй подарок. При передаче NFT новый владелец получает активную запись, а предыдущая остаётся в истории без права закрепления.

Назначения относятся к VisuGram и не меняют права на реальные активы Telegram/TON. Старые локальные подарки автоматически на сервер не импортируются: их исходные даты и сообщения сохраняются локально. Для закрепления старого объекта в общей БД добавьте его через серверное оформление.

## Локальный запуск и VPS

```sh
cd server
python app.py
```

API слушает `127.0.0.1:8080`. Для VPS можно использовать `docker compose up -d --build` и свой HTTPS-прокси. Клиент разрешает HTTP только для localhost; удалённому серверу нужен HTTPS.

SQLite, включая WAL, находится в Docker volume `visual_data`. Команда `docker compose down -v` уничтожает этот диск. Для согласованной копии используйте SQLite backup API:

```sh
docker compose exec api python -c "import sqlite3; s=sqlite3.connect('/data/visugram.sqlite3'); d=sqlite3.connect('/data/backup.sqlite3'); s.backup(d); d.close(); s.close()"
docker compose cp api:/data/backup.sqlite3 ./backup.sqlite3
```

Резервная копия содержит данные пользователей; не публикуйте её в GitHub. На Railway можно выполнить тот же Python backup через SSH/CLI сервиса и скачать файл средствами Volume. Доступность автоматических резервных копий зависит от плана.

## Ограничения

До 1000 серверных записей подарков на аккаунт, 20 визуальных имён и шести закреплённых подарков. Есть ограничения размера запросов и частоты обращений. Межсерверной синхронизации нет. При недоступном API закэшированные данные остаются доступны, новые назначения не подтверждаются локально.

Оператор имеет доступ к базе. Перед публичным запуском дополните [проект политики](privacy.md) контактом оператора и сроками хранения. API не ведёт журнал доступа и не принимает ключи Telegram или TON-кошелька.

## API

POST-запросы содержат JSON и заголовок `X-VisuGram-User-Id` с числовым ID. Изменения требуют `operation_id`; профиль также требует актуальную `revision`. ID передаются строками.

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/health` | Доступность |
| POST | `/v1/sync` | Регистрация, базовый юзернейм, курсор, профиль и история подарков |
| POST | `/v1/profile` | Проверка и закрепление имён/номера |
| POST | `/v1/profile/view` | Визуальный профиль и видимые подарки |
| POST | `/v1/gifts` | Выдача или передача подарка |
| POST | `/v1/gifts/manage` | Закрепление и скрытие полученного подарка |
